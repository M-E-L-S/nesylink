# 实验报告：在Lean 4中对关卡机制的形式化验证与路径搜索

## 1. 任务概述

本报告描述的是在Lean 4中对“Task 1-5”游戏关卡进行形式化建模与策略验证的任务。通过 task1-5.lean五个各司其职的lean文件，分别对每一个不同的关卡进行了针对性建模，将游戏的状态空间、动作空间及物理规则转化为逻辑谓词，并证明了在该模型下，我们设计的agent能够达成任务目标。

## 2. 模型假设与抽象

为确保形式化验证的可行性与可计算性，本项目对游戏环境进行了以下抽象：

* **地块抽象**：把复杂的像素渲染简化为以`Tile`地块为最小单位设计，同时也把移动设计为以地块为单位，而不是一次操作。
* **时间/HP 机制**：针对task5的毒雾设计，抽象为离散的步数计数器 `steps`。每移动一次，步数加 1。同时为了同步上述的操作简化，移动操作有6倍的缩放。所以使用 `steps % 33 == 0` 的规则执行 HP 自动扣除逻辑。

## 3. 形式化思路与核心逻辑

### 3.1 状态与动作定义

* **状态定义**：使用 `SymbolicState` 封装玩家坐标、房间逻辑、资源（金币/钥匙/治疗）、以及陷阱与怪物状态。
* **动作空间**：定义了 `Action` 类型，覆盖 `wait`, `up`, `down`, `left`, `right`, `interact`, `attack`。
* **对象**：定义了`room`等实际对象，用以表征游戏中的具体对象。
* **目标定义**：通过 `GoalReached` 谓词定义了任务完成的条件，确保在状态演化过程中，最终状态满足所有目标要求。

### 3.2 转移语义

* **游戏机制刻画**：针对不同的task全量实现了其中出现的所有游戏机制，包括移动、非法移动block，开箱、攻击、毒雾、按钮切换等。
* **安全性守恒**：证明核心定理 `safe_step_preserves_safe_state` 证明了无论执行何种合法动作，只要初始状态安全，变换后的状态依然满足 `isSafeTileB`，确保了动作的安全性。

### 3.3 证明策略
基于我们设计的状态机与搜索agent，实现以下证明：
* **模块化验证**：采用子路径（Phase）分段验证状态机的不同状态。通过 `exec_append` 定理证明了路径连接的可结合性，将长序列分解为多个 Phase 进行逐一验证。
* **完整性支持**：证明 `task1-5_completable_if_subplans_exist` 关键定理，实现了从分段路径到整体任务完成的逻辑推导，证明了状态机设计是可以满足任务目标的。
* **可达性验证**：针对每个任务构造了具体实现方案，证明了关键定理`task1-5_concrete_completable`，证明了搜索设计是可以满足局部状态目标的，同时`runPlanFn` 输出的路径已通过 `decide` 验证，满足所有安全谓词，保证路线合法。结合上述定理，说明状态机搜索agent足以满足完整的任务目标。
* **完备性证明**：针对启发式BFS动作搜索的agent具体决策方式，证明了关键定理 `bfs_frontier_complete`，说明了若存在有限步的可行路径则该搜索算法一定可以找到。

## 5. 结论

本项目通过学习仿照助教给出的KillMonsterFormalization.lean实现，成功构建了能够严谨描述 Task 1-5 环境的逻辑模型。通过形式化证明，我们不仅确认了所设计的行动规划在逻辑上是安全的，而且证明了该规划在给定的环境规则下，能够稳定地从初始状态演化至满足 `GoalReached` 的目标状态。
